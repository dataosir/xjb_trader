# 03 · 交易运营日 SOP

> **分工**：本页管「人怎么不逃避运营」；**命令、时刻、菜单**以 [`../prd/02-daily-workflow.md`](../prd/02-daily-workflow.md) 为准。  
> 帽子与时间占比见 [`00-operator-hats.md`](00-operator-hats.md)。

---

## 0. 使用方式

- **交易日**：开盘前过一遍 §1 + §2；收盘后过 §4。  
- **非交易日**：只做 §1 晨间（读 `project-state`）+ §4 晚间（若本周未全量 `review` 则补跑）。  
- 可复制 §5 模板到个人笔记，**不必**提交到仓库。

---

## 1. 晨间启动（约 5 分钟）

> **主帽**：交易员。目标：今天不偏航，不拿改代码代替跑纪律链。

### Checklist

- [ ] 读 [`../project-state.md`](../project-state.md)「当前焦点」与「明确不做」  
- [ ] 确认今日主帽：**默认交易员**；若昨日策略研发 >50%，今日强制交易员优先  
- [ ] 看昨日/最近一次 `seed-plan` 或 `review` 的**缺口看板**一行摘要（待 T+3、低吸条数、影子桶样本）  
- [ ] 定下今日 **MIT ≤3**（见下表范例，选填实项）  
- [ ] **成功定义**写一句话：例：「跑通 seed-plan + 待 T+3 不增」

### MIT 范例（证据阶段）

| 优先级 | 范例 | 对应命令/文档 |
|---|---|---|
| MIT-1 | 14:30 前完成 `seed-plan` | 菜单 `3` / `tea seed-plan` |
| MIT-2 | 压待 T+3：全量或轻量回填有进展 | `review` / 种子收尾自动回填 |
| MIT-3 | **零改 config**；调参冲动只写反馈日志 | [`02-user-feedback.md`](02-user-feedback.md) |

**非交易日 MIT 调整**：MIT-1 改为「补跑上周未做的全量 `review`」；仍保持零改 config。

### 禁止晨间做的事

- 打开 IDE「先修个小问题」再跑种子  
- 因可买 EMPTY 多而讨论降门槛（先确认突破/过热闸）  
- 未读 `project-state` 就改 `config`

---

## 2. 盘中 / 交易时段（按日工作流）

> 本节**不重复**时刻表；只补充运营者约束。

### 2.1 按 [`02-daily-workflow`](../prd/02-daily-workflow.md) 执行

| 时段 | 运营者记住 |
|---|---|
| ~13:30 | 天气只影响姿态，不把「未硬禁」读成鼓励买入 |
| **~14:30** | **硬 MIT**：`seed-plan` 收尾看回填一行摘要 |
| ~14:35 / 次日 09:35 | `plan-check`：要素漂移 → 整单作废，不凑合 |
| T+1 14:00–14:45 | 仅计划内 `run`；破窗 = 纪律事件，记周报 |
| 收盘后 | 全量 `review` 或确认轻量回填已消化 |

### 2.2 盘中帽子规则

- **交易员帽**：菜单 1–8、准入、持仓；禁止边看盘边改 `screener.py`  
- **策略研发帽**：盘中默认**关闭**；仅 CI 红/生产 bug 可例外，且须 MIT 写明  

### 2.3 冲动拦截

| 冲动 | 正确处理 |
|---|---|
| 「今天可买太少，改一下阈值」 | 写反馈日志一行；对照 B-P0-03/03b 是否闸生效 |
| 「低吸空池全是 0，放宽一关」 | 只读 `lowbuy_pool_diag`；backlog B-P0-07 Won't |
| 「影子桶太差，关掉 shadow」 | 继续攒样本；未达 `shadow_min_samples` 不调策略 |
| 「加个新因子试试」 | 记入 backlog P2；不开 PR |

## 3. 深度工作块（可选，非交易日下午）

若当日无行情且 MIT 含文档/修复：

- 单次 **≤90 分钟**策略研发块  
- 开始前写清：关联 backlog ID / Issue  
- 结束必跑 `tea selftest`（若动代码）  
- 仍须满足 [`00-operator-hats`](00-operator-hats.md) ≤30% 周均（非单日豁免）

---

## 4. 晚间收尾（约 10 分钟）

> **主帽**：交易员复盘；有研发提交则核对是否越界。

### Checklist

- [ ] **MIT 对照**：完成 / 卡住（原因）/ 砍掉（原因）  
- [ ] 今日是否跑通 `seed-plan`？回填摘要是否看过？  
- [ ] 本周是否已 ≥1 次全量 `review`？（周五前必须 yes）  
- [ ] 今日是否改 config / 合并策略 PR？若是 → 是否违反「样本门槛」或缺少 CHANGELOG？  
- [ ] **心流审计**（一句话）：今天是在攒证据，还是在用研发逃避复盘？  
- [ ] **明日 1–2 个 MIT** 预写（默认含 seed-plan 或 review）  
- [ ] 调参/策略冲动未处理 → 追加 [`02-user-feedback.md`](02-user-feedback.md) 一行  

### 纪律红灯（记入周报或反馈日志）

| 事件 | 动作 |
|---|---|
| 实盘 FORCE / 破买入窗 | 优先查纪律，**不**先改闸门 |
| 连续 2 个交易日未 `seed-plan` | 次日 MIT-1 强制种子 |
| 待 T+3 一周只增不减 | 查是否漏 `review`；见 Ops-2 里程碑 |
| 策略研发连续 2 日 >50% 时间 | 第三日强制交易员 100% |
