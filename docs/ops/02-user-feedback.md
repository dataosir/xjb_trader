# 02 · 用户反馈与缺陷收集

> 运营层：反馈怎么进迭代，不与 `data/` 运行日志混淆。

---

## 1. 入口

| 来源 | 怎么记 | 何时进开发 |
|---|---|---|
| GitHub Issue（Bug / 规则讨论） | Issue 本身 | Triage 后开 Plan → 改 Fxx |
| 本人盘中/盘后体感 | 本页「反馈日志」追加一行 | 与种子证据冲突时优先信数据 |
| selftest / CI 失败 | CHANGELOG + 修复 PR | 立即 |

## 2. 分类标签（建议）

- `bug`：行为与 PRD/文档不符  
- `strategy`：可买口径 / 胜率 / 闸门（必须带样本证据）  
- `ux`：CLI 文案 / 菜单  
- `data`：行情源 / 缓存 / 缺字段  
- `nfr`：性能、依赖、打包  

策略类反馈**禁止**无样本调参；对齐 [`../prd/05-roadmap-backlog.md`](../prd/05-roadmap-backlog.md) 的 Won't now。

## 4. 与 4 步闭环的衔接

反馈若触发开发：Sync（本页 + project-state + 相关 Fxx）→ Plan → Code & Doc → Log。  
纯吐槽、无复现、无样本：只记本页，不改阈值。
