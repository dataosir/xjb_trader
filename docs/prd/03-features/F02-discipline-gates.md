# F02 · 纪律门禁（法）

## 1. 背景与目标

在「术」之前用硬纪律拦截冲动交易：无计划、错窗口、超额评估、连亏冷却、姿态禁止等。**不可跳过**是产品硬约束。

## 2. 用户故事 / 场景

- 计划外代码 `run` → 直接拒绝。  
- 非 14:00–14:45 新开 → 拒绝（`--any-time` 仅演练）。  
- 连亏达阈值 → 冷却，除非 `--force` 且已复盘约定满足。

## 3. 功能范围

**In**

- 会话级 / 代码级 / 买入级门禁（`check_session_start` / `check_code_gate` / `check_buy_gate`）  
- 单日计数：新开、评估、同标复筛  
- 计划绑定、买入窗口、姿态/高潮限制、连亏冷却  
- `gate` / `status` 展示与谨慎重置  

**Out**

- 改写共振分数（F04）  
- 自动清计划（属 F07，可联动提示）  

## 4. 主流程与边界

1. `run` 开始：会话门禁（天气姿态、日限额等）。  
2. 指定代码：计划内？同标复筛次数？  
3. 真正登记买入前：买入窗 + 买级门禁。  

**边界**：README 曾述「上证 MA20 下方禁止评估」——策略侧已改为共振分级扣分；门禁以**当前代码与配置**为准，PRD 以 `gates.py` + CHANGELOG 为准。

## 5. 关键配置键

| 键域 | 用途 |
|---|---|
| 买入窗口起止 | 默认 14:00–14:45 |
| 单日新开/评估/复筛上限 | 如每日最多新开 1、评估 5、同标 2 |
| 连亏冷却阈值 | 连续亏损 → 冷却天数 |

（点号路径以 `config_store.DEFAULTS` 为准。）

## 6. 代码锚点

- `tea/screening/gates.py`  
- `tea/runtime/runner.py` · `run_once`  
- CLI：`tea gate [--reset]`、`tea status`

## 7. 验收标准

- [ ] 无计划 / 代码不在计划 → `run` 拒绝  
- [ ] 窗口外无 `--any-time` → 拒绝新开  
- [ ] 超额评估/新开 → 拒绝并留痕于 `daily_state`  
- [ ] 不接受「一键跳过全部纪律」的产品改动（CONTRIBUTING）  

## 8. 已知缺口 / 待迭代

- 门禁文案与 README 个别历史表述可能不同步，改门禁时需同步 README + 本 PRD  
- `--force` / `--any-time` 仅演练用途，文档需持续强调风险
