# F07 · 计划生命周期

## 1. 背景与目标

交易计划是纪律锚点：种子写入 → 复核锁定 → 次日执行 → 过期清除/作废。任一关键要素变动可**整单作废**，防止「计划漂移后仍交易」。

## 2. 用户故事 / 场景

- `seed-plan` 写出次日计划。  
- `plan-check`：板块/价格要素变化 → 作废。  
- `plan --invalidate` / `plan-clear`：手动收尾。  
- `run` 只接受有效计划内代码。

## 3. 功能范围

**In**

- 计划 CRUD：查看、清空、作废、清过期  
- 复核：快照比对；`prefer_sector` 用快照板块避免 industry 重映射  
- 过期检测与菜单提示清除  

**Out**

- 自动下单  
- 低吸/胜率影子写计划  

## 4. 主流程与边界

1. 写入：可买列表 + 元数据（日期、板块戳记、阈值快照等）。  
2. 复核：现价/板块/关键字段 vs 快照；`--dry` 只比对。  
3. 失效：标记理由，门禁视为无计划。  
4. 清除：过期计划收尾，备注留痕。  

**边界**：复核必须优先使用计划快照中的 `sector_bk/name`，与 F03 入选一致性同一哲学。

## 5. 关键配置键

| 键域 | 用途 |
|---|---|
| 计划有效期 / 过期规则 | 见 `plan` 与 strategy 配置 |
| 种子写计划开关 | CLI `--no-plan` |

## 6. 代码锚点

- `tea/portfolio/plan.py`  
- `tea/runtime/runner.py` · `seed_plan` / `plan_check`  
- CLI：`plan` / `plan-check` / `plan-clear`

## 7. 验收标准

- [ ] 无有效计划时 `run` 拒绝  
- [ ] 复核发现关键变动 → 整单作废并留理由  
- [ ] `--dry` 不落盘  
- [ ] 原子写入 `trade_plan.json`  

## 8. 已知缺口 / 待迭代

- 用户曾手动删「可买」计划（信任度问题）→ 产品层需靠胜率纠偏重建信任，而非放松复核  
- 过期提示与菜单联动需保持友好但不自动静默清掉证据
