## [Unreleased]

### 策略

- **涨幅窗口下限动态化**：根据当日最强板块涨幅自适应（≥5% → 3.0%，4~5% → 2.5%，<4% → 2.0%），弱市不再系统性空仓。硬地板 2.0%（再低 R:R 撑不到 ≥3）；影响严格档 / 萌芽窗口 / 热点降级档，动量档（5.0%）不变，严格档上限 5.5% 不变（窗口只变宽）
  - 板块排序里的「温和票结构分」与系统分的「涨幅贴合」同步跟随动态下限，否则窗口放宽了但打分还按 3% 数，白放宽
  - 前夕观察上限跟着收（下限降到 2.5% 时前夕窗为 1%~2.5%），避开与严格窗重叠——否则同一只票两边都进，「等它涨入严格窗」的触发条件当场自相矛盾
  - 扫描输出 / SEED 报告新增一行「动态窗口：下限 2.5%（最强板块 +4.30%，标准 3.0% → 下调至 2.5%）」，当前用的是什么阈值一眼可见
  - 新增配置：`seed.dyn_min_chg_enabled`（置 false 回到固定下限）/ `dyn_min_chg_floor` / `dyn_strong_sector_chg` / `dyn_weak_sector_chg`

### 体验

- **数字菜单从 20 项平铺改为按时段推荐 4 项**：同一时刻真正有意义的操作不超过四个，平铺 20 项只会让人每次重新读一遍。`m` 展开全部（按道法 / 准入 / 计划 / 持仓 / 复盘 / 工具 分六组），`c` 收起。**编号不重排**，1-20 任何时候都能直接输，没列出来的也能输
- 菜单里直接回车不再报「无此选项」，只重印菜单
- **切数据源时屏上说清「谁挂了、改用谁」**：原先只有一句含糊的「⏳ 网络抖动，正在重试...」刷屏，用户既不知道是哪一步在抖，也不知道降级到底有没有生效。现在降级链每次切源直接报 `⏳ 东财行情失败（请求失败(2次): ...），改用 腾讯 数据源...`；链尾无备源时报「已无备用数据源」。通用重试提示保留但节流放宽到 5s（`market.retry_notice_gap_sec`），不再和切源提示叠着刷
- 取数收尾新增一行数据源命中账：`网络请求 68 次｜东财 45｜腾讯 18｜失败 0`（种子扫描 / 天气 / 筛选共用），降级链是否真的在干活一眼可见
- **计划绑定相关提示补全股票名**：光一串代码认不出是哪只票。种子扫描「宁缺毋滥」分支的旧计划提醒、代码门禁 `check_code_gate` 的「计划绑定」拦截文案、`gates.format_status` 的今日状态行，全部从裸代码列表改为「代码 名称」（计划里没记名字时回退到裸代码）；`status.plan_codes` 与 `planned_codes()` 语义保持不变，机器字段仍是纯代码

### 修复

- **东财 `clist` 接口硬限 100 行/页，配置里却写着 `pz=6000`**：`pz` 填多大都不报错，只是默默地只回 100 行；叠上 `po=1&fid=f3`（按涨幅降序），拿到的是涨幅榜前 100 名——数据看着完整，实际是极端偏样本。现在按接口自报的 `data.total` 真正翻页：
  - `get_breadth` 的涨跌比不再结构性恒为 100%。全市场五千多只按 100 行/页翻完要 56 次请求，与防封目标冲突；但列表按涨幅降序，「涨幅 > 阈值」是一段前缀，于是二分定位到跨界那一页、页内线性数一遍，得到**精确值**。实测 9 次请求拿到 5545 只的确切涨跌家数。返回值新增 `exact` 标记探测预算是否够用
  - `get_sector_members` 翻完整个板块。之前只取前 100 名对种子扫描是致命的——它要找的正是 3.0~5.5% 的温和票，而这些票全在涨幅榜前 100 名之外，等于在一个结构性不含目标的样本里搜索
  - `get_sector_ranking` 不再停在 300 个板块（3 页 × 100），实测 5 次请求拿全 496 个
  - 板块磁盘缓存加版本号：翻页修好前落盘的缓存只有 300 个板块，24h 内会被读回来把修复盖住
  - 请求量实测：涨跌家数 9 次 + 板块排名 5 次 + 前 30 板块成分 31 次 = 45 次（前 30 个板块里只有 1 个超过 100 只，所以成分部分只多花一次请求）
- **非交易日情绪输入日期不一致**：指数 / 板块 / 涨跌比都会自动给上一个交易日，只有按日期取的涨停池返回 0，于是出现「涨停 0 家」旁边坐着「前5板块均涨 10.31%」——情绪公式拿这两个不同日子的数做加减，算出来的周期是假的。`get_limit_up_stats` 未指定日期时按交易日往前回退（默认最多 3 天），并在屏上标出它到底是哪一天的数据
- **涨停池的 `ut` 令牌一直是错的**：接口回 `rc=205, data=null`，于是涨停家数永远是 0、最高连板永远是 0。已换成正确令牌（实测拿到涨停 62 家 / 最高 6 板）
- **取数失败不能假装成「今天没有涨停」**：这是上一条真正危险的地方。当成 0 后，情绪公式会拿「0 板」扣 10 分，还可能触发冰点降仓把半仓乘数强制打到 0.25——一个网络 / 令牌问题悄悄变成了减仓指令。现在 `rc非0` 返回 `None` 并标 `ok=False`，情绪公式遇 `None` 直接跳过该项，屏上另行提示数据缺口
- 涨停家数改用接口自报的 `tc`：`pool` 被 `pagesize` 截断时 `len(pool)` 会偏小
- **指数取数失败时屏上写着「上证在 MA20 下方」**，实际是不知道。拦住新开这个方向对一个纪律引擎是对的（保守），但话得说准：现在显示「未知」并注明原因。更进一步——点位（走 `quote` 池，有 `push2delay` 兜底）与 MA20（走 `push2his` 那族，常被单独封）本是两路，旧代码 K 线一挂就把已到手的点位一起丢，屏上「上证 —（—）」。现在只丢 MA20、保留点位（`上证 3806 … MA20 — → 未知`）；且「不知道 MA20」不再被退潮判据当成「在 MA20 下方」编出假退潮（周期照分走主升 / 发酵，姿态仍落防守）
- **「姿态=防守」的理由把三个候选原因一股脑印出来**，于是出现「情绪分 84」旁边写着「情绪分偏低」。现在只列真正触发的那几条并带上具体数值
- **本机配了翻墙代理时东财请求全崩（`ProxyError`）**：东财是国内站，但 shell 里为 GitHub 等设的 `http_proxy` / `https_proxy` 会被 requests 默认读走，把域名请求硬塞进代理，代理一连不上就 `Unable to connect to proxy` 全线失败——屏上表现为指数 / 板块 / 涨跌比全是「数据缺口」。现在默认 `trust_env=False` 直连，忽略环境里的代理；境外等真需要代理取数的场景置 `market.use_env_proxy: true` 或直接配 `proxy_pool`
- 取数失败时涨跌比括号里漏印成字面量 `涨 None / 跌 None`，现在渲染为 `涨 — / 跌 —`
- **CDN 节点按个坑时，坏节点会拖垮整次取数**：实测 `push2` / `push2his` 某些节点直接 `RemoteDisconnected`，而 `push2delay` 这类节点是通的。旧轮换每次 `random.choice`，一次操作里多个请求各自随机挑节点，可能三次重试全撑在同一个坏节点上，而且不记事——上一个请求刚确认 push2 死了，下一个又去撞（这就是为何同一节点池下板块成功而涨跌比失败）。现在：同一次 `get_json` 的多次重试走不同节点；连接失败的节点记入会话黑名单，后续请求先活后死排序（成功则自动复活，整池全坏仍会把每个节点都试一遍）。kline 节点池从 2 个扩到 4 个（`push2his` / `1` / `2` / `7`）。单次请求的尝试次数取 `max(retries, 节点数)`——老配置把 `retries` 钉在 3、而 kline 池有 4 个节点时，也保证每个节点都轮得到；且加载配置时始终把 DEFAULTS 里的 CDN 节点并进用户配置（`save()` 落的是全量配置，否则新增的官方镜像节点进不来已有配置）。实测：在 `push2` / `push2his` 均被封的环境下，默认配置无需手工指定主机即可拿全指数 / 涨跌比 / 板块 / 涨停池
- 行情与 K 线接口从 `http://` 改为 `https://`（`clist` / `ztpool` 本来就是 https）
- **东财 `fltt=2` 返回值被错误除以 100**：`fltt=2` 返回的已经是最终浮点数（放大 100 倍的整数是 `fltt=1`）。`_parse_quote` 与 `get_index` 还在除 100，导致上证 3832 点显示成 38.32 点；而 MA20 来自 K 线（真实点位），于是「上证在 MA20 下方 → 禁止新开」这条门禁**永久锁死**。个股侧同样受影响（价格 / 涨幅 / 量比 / 换手率全部小 100 倍）
- 11:30–13:00 的时段名从「盘后」改为「午间休市」
- **Windows 上输出被重定向时程序直接崩溃**：输出不是直连控制台（管道、`> file`、CI 日志）时 Python 用 ANSI 代码页（cp1252 / cp936），而本程序文案全是中文，第一句 print 就 `UnicodeEncodeError`。现在入口处统一把 stdout / stderr 切到 UTF-8
- `.gitignore` 的 `data/` 未锁定根目录，连 `tea/data/`（行情数据层包）一起忽略掉了；已改为 `/data/` 与 `/reports/`
- **5 源降级默认没启用，等于白实现**：`market.data_sources` 默认只有 `["eastmoney"]`，降级链上就一家，东财一抖整轮取数照样全崩——用户看到的仍是满屏「网络抖动」加二十几个板块「拉取失败」。现在默认五家全开（东财 / 腾讯 / 新浪 / 网易 / 凤凰）
  - 单源时代已落盘的老配置会在下一次启动时**自动升级一次**（屏上一次性提示；标记写在 `meta.multisource_migrated`，重复启动不再动手）。用户显式配了别的组合（例如只留东财+腾讯）则原样尊重，只打标记不覆盖
  - 同源重试 `market.retries` 4 → **2**：后面还有四家备源，在第一家身上死磕 4 次 × ~3s 只是把降级往后拖十几秒
  - 板块成分（东财独家、扫一轮要问 30 次）的重试单独压到 `market.member_retries: 2`，用完即还原，不影响其余取数点的全局重试预算

## [1.0.0] - 2026-08-02

首个完整版本。按"道-法-术"三层框架从零实现 A 股交易准入引擎。

### 道（市场天气）

- 情绪评分：基准 50 / 上限 100，六项加减（涨跌比、最高连板、上证 MA20 位置与涨跌幅、热点板块数、前 5 板块均涨）
- 周期判定：冰点 / 修复 / 发酵 / 主升 / 高潮 / 退潮
- 交易姿态：空仓 / 防守 / 进攻，含"高潮易分歧"禁新开
- 冰点降仓：最高连板 ≤3 且涨跌比 <35% → 半仓乘数强制 ×0.25
- 交易窗口与阶段判定（`timing`），情绪快照 120s 内存缓存

### 法（纪律门禁）

- 三道门禁：会话门禁、代码门禁、买入门禁
- 计划绑定作为核心纪律：今日无有效计划或代码不在计划内 → 禁止评估与买入
- 买入时间窗 14:00–14:45；单日最多新开 1 笔 / 评估 5 次 / 同票复筛 2 次
- 上证 MA20 下方禁止评估新开；连亏冷却
- 动态门槛：基准 6，杂毛 +1、样本不足 +1、防守姿态 +1，种子龙头 -1（下限 6）
- 仓位 3/7 灰度确认制，半仓乘数 = 情绪 × 期望值 × 跟涨，夹紧 [0.25, 1.0]
- 期望值 E[R] = p̂ × odds − (1 − p̂)，样本不足时按默认胜率 0.40 并标记
- 计划复核：逐项对比快照，任一变动整单作废

### 术（个股评分）

- 9 分共振六维：板块强度 2 / 大盘趋势 1 / 消息面 1 / 市值区间 2 / 量价结构 2 / 止损结构 1
- 身份判定 100 分 6 维，龙头 ≥70 / 跟风 ≥45 / 杂毛 <45，≥2 个负面 flag 强制降为杂毛
- 热点板块相对跟涨：相对系数 0.42~0.90 → +18，板块前排额外 +12
- ATR(14) 优先的止损止盈：止损 clamp(ATR%×1.5, 2%, 8%) 硬顶 6%，止盈 min(ATR%×3, 15%)
- 含滑点 R:R（买入 +0.5% / 止损 -0.5%），要求 ≥3，不足则抬止盈反推
- VETO 一票否决：硬否决 6 项 + 软否决 4 项，20cm 板阈值等比 ×2

### 扫描与计划

- 种子扫描四步流：板块综合排序 → 三档涨幅窗筛选 → VETO → 预审快照与三档输出
- 观察池闭环：纳入 / 剔除 / 回踩就绪
- 落选追溯：`seed_trace.jsonl` + `SEED_TRACE.md`，记录每一步淘汰了谁
- T+1 跟涨经验回填，按阶段×档位×轨道聚合胜率
- 当日累积（回答"为什么今天没交易"）、统计归因、周复盘

### 工程

- CLI：23 个子命令 + 20 项数字菜单，交易逻辑全部下沉，`cli.py` 不含策略
- 一键启动：`run.sh`（macOS / Linux）与 `run.bat`（Windows，可双击），自动挑 3.8+ 解释器、把数据目录锁在仓库根、参数原样透传；CI 在三个平台各启动一次
- 分层：行情数据层拆为 `tea/data/`（indicators → cache → fetcher → market，依赖单向无回边），四阶段流程拆为 `tea/phases/`（results / prompt / session / phase1~4）；两个子包的 `__init__.py` 只做再导出
- 配置：363 个可调参数，JSON 深合并，缺项自动回落默认值，新增参数自动生效
- 行情：东方财富 push2 系列接口，随机 UA/Referer、请求延时、代理池、指数退避重试、板块成分多级缓存
- 三路数据并行采集，单路失败降级不影响整体
- 所有文件写入原子化（先写 `.tmp` 再 `rename`）
- 运行时零第三方依赖；`requests` 为可选加速项，缺失时回退 `urllib`
- 离线自测 97 项断言，全部按规格独立重算后比对，沙箱运行不触碰真实数据

### 已知限制

- 离线自测不触网，**东财接口的真实连通性与字段映射尚未经实盘验证**
- 观察池闭环与防封策略没有自动断言覆盖
