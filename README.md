# XJB_TRADE (TEA) — A 股交易准入引擎

[![CI](https://github.com/dataosir/xjb_trader/actions/workflows/ci.yml/badge.svg)](https://github.com/dataosir/xjb_trader/actions/workflows/ci.yml)
[![Python](https://img.shields.io/badge/python-3.8%2B-blue.svg)](https://www.python.org/downloads/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![自测](https://img.shields.io/badge/selftest-352%2F352-brightgreen.svg)](#十离线自测)

> 计划你的交易，交易你的计划。宁可空仓，不强行凑票。

这不是选股软件，是**准入引擎**。它的默认答案是"不买"，只有当道（市场天气）、法（纪律门禁）、术（个股共振）三层同时点头，才会放行一次开仓。

引擎不预测涨跌，只回答一个问题：**今天这一笔，够不够资格下手？**

---

## ⚠️ 风险与免责声明

**本项目仅用于个人学习与交易纪律研究，不构成任何投资建议。**

- 引擎输出的 `BUY` 只表示“本笔符合预设纪律条件”，**不是盈利保证**，也不预测价格。
- 股市有风险，入市需谨慎。**你的盈亏完全由你自己负责**，作者不对任何交易结果承担责任。
- 行情数据来自第三方公开接口，**可能延迟、出错或随时停服**。下单前请以券商客户端为准。
- 引擎**不对接任何券商交易接口，不会自动下单**。所有买卖需你手动执行。
- 请自觉控制请求频率，避免给数据提供方造成压力。

首次使用强烈建议：先用 `eval`（只算不买）空跑至少两周，确认引擎的判断与你的认知一致后，再考虑小资金实盘。

## 一、三层框架

| 层 | 职责 | 模块 |
|---|---|---|
| **道** | 市场天气：情绪分 → 周期 → 交易姿态 → 仓位乘数 | `sentiment.py` `timing.py` |
| **法** | 纪律门禁：计划绑定、时间窗、单日限额、连亏冷却、仓位与期望值 | `gates.py` `plan.py` `portfolio.py` `expectancy.py` |
| **术** | 个股评分：身份判定、9 分共振、ATR 止损止盈、VETO 一票否决 | `identity.py` `preflight.py` `veto.py` `screener.py` |

三层是**串联否决**关系，不是加权投票 —— 任一层否决，整笔作废。

## 二、安装与运行

零第三方依赖，只需 Python 3.8+（仅用标准库 `urllib` / `json` / `concurrent.futures`）。已在 Linux / macOS / Windows 与 Python 3.8 至 3.13 上通过 CI。

### 方式一：一键启动脚本（最省事）

```bash
git clone https://github.com/dataosir/xjb_trader.git
cd xjb_trader

./run.sh                    # 进入数字菜单
./run.sh selftest           # 离线自测
./run.sh eval 600519        # 子命令原样透传
```

Windows 用 `run.bat`，可直接双击：

```bat
run.bat
run.bat selftest
```

脚本只做三件事：找到 3.8+ 的解释器（找不到就明确告诉你缺什么，而不是报一堆堆栈）、把数据目录锁在仓库根目录、把参数原样交给引擎。不装包，不建虚拟环境。

两个可选环境变量：`TEA_PYTHON` 指定解释器（如 `TEA_PYTHON=python3.12 ./run.sh`）；`TEA_HOME` 指定数据目录，你设了就以你的为准。

> 锁定数据目录这一步不是多余的：引擎默认把配置与持仓写在**当前工作目录**，不锁的话从不同路径启动会生出好几套互不相干的数据。

### 方式二：安装为命令

```bash
git clone https://github.com/dataosir/xjb_trader.git
cd xjb_trader
pip install .

tea                         # 进入数字菜单
tea --help                  # 查看全部子命令
```

想让抓取更稳（连接复用）可装上可选的 `requests`；不装则自动回退 `urllib`，功能不变：

```bash
pip install ".[fast]"
```

### 方式三：不安装，直接跑源码

```bash
git clone https://github.com/dataosir/xjb_trader.git
cd xjb_trader

python3 -m tea              # 进入数字菜单（推荐）
python3 -m tea --help       # 查看全部子命令
python3 -m tea selftest     # 离线自测，不联网，验证公式与规格对齐
```

下文命令统一写 `tea xxx`，换成 `python3 -m tea xxx` 或 `./run.sh xxx` 完全等价。

### 初始配置

**第一次进菜单会自动弹配置向导**，把因人而异的那几项问一遍（总资金，一组选股与风控阈值：单笔最大仓位、选股涨幅上下限、市值上下限、最低 R:R、共振分门槛，再加板块交易权限与数据源降级链），其余参数留默认。每项都可直接回车取默认，也可选「1. 全部使用推荐默认值」一键开跑。完成后写 `meta.initialized`，不再重弹；想重新配置走菜单 `21` 或：

```bash
tea setup             # 重跑配置向导（当前值作为默认值）
tea setup --defaults  # 不提问，直接采用推荐默认值
```

向导之外，所有参数仍可随时手改。`tea_config.json` 在首次保存配置时落盘，`data/` 首次运行时建立，`reports/` 首次出报告时建立：

```bash
tea config count      # 参数总数与配置文件路径
tea config list       # 全部参数（点号路径）
tea config set strategy.pass_threshold 7
```

资金也可单独改——不告诉引擎本金，可用资金就是 0、算不出仓位：

```bash
tea capital 100000
tea status            # 确认门禁计数 / 计划 / 持仓
```

数据目录可用环境变量改写，便于多账户或沙箱：

```bash
TEA_HOME=~/my_trade tea
```

> `tea_config.json`、`data/`、`reports/` 已写入 `.gitignore`。它们含你的本金、持仓、代理池等私有信息，**不要提交到公开仓库**。

### 数字菜单

不带子命令直接运行就进菜单。菜单**默认只列此刻该做的四件事**，按当前时段自动变：

```
XJB_TRADE (TEA) 1.0.0　2026-08-03 14:10 | 买入窗口(14:00-14:45) | 买入窗口=开
  此刻（买入窗口(14:00-14:45)）建议：
   3. 单标的准入评估（Phase1→4）
   7. 查看交易计划
   5. 种子扫描 + 写次日计划（14:30）
  10. 持仓 / 资金
   m. 展开全部 21 项
   q. 退出　│　1-21 任意编号都可直接输入
```

| 输入 | 作用 |
|---|---|
| `1`–`21` | 直接执行对应功能。**编号永不变**，没列出来的也能输 |
| `m` | 展开全部 21 项（按道法 / 准入 / 计划 / 持仓 / 复盘 / 工具 分组） |
| `c` | 收起，回到四条建议 |
| 直接回车 | 重印菜单（不算选错） |
| `q` | 退出 |

为什么默认不全列：同一时刻真正有意义的操作从来不超过四个。非交易日只能复盘和演练，买入窗口外再怎么评估也会被门禁拦回——把全部选项平铺在眼前只会让人每次重新读一遍。

## 三、每日时间线

引擎的纪律是**跨日闭环**：T 日收盘前选种子写计划，T+1 日只执行计划。当天临时起意的票一律买不进去。

| 时刻 | 动作 | 命令 |
|---|---|---|
| 13:30 | 观察扫描，看盘面强弱 | `weather` |
| **14:30** | **种子四步流 → 写次日计划** | `seed-plan` |
| 14:35 | 计划复核（任一要素变动 → 整单作废） | `plan-check` |
| 收盘后 | 跟涨回填 + 观察池复核 + 当日累积 | `review` |
| T+1 10:00 | 隔夜复核，计划是否还成立 | `plan-check` |
| **T+1 14:00–14:45** | **唯一买入窗口，执行计划** | `run <代码>` |
| 每周五 | 周复盘：纪律自查 + 归因 | `weekly` |

> 为什么买入窗口是 14:00–14:45：尾盘方向已明、当日情绪已定型，避免上午被假突破反复骗手。

## 五、核心公式

### 情绪分（道，基准 50 / 上限 100）

涨跌比、最高连板、上证 MA20 位置与涨跌幅、热点板块数、前 5 板块均涨 —— 六项加减得分，映射到周期：

```
冰点 <35 │ 修复 <50 │ 发酵 <70 │ 主升 ≥70 │ 高潮 │ 退潮
```

姿态：`空仓`（<40 或冰点，禁止新开）→ `防守`（<55 或 MA20 下）→ `进攻`。

**冰点降仓**：最高连板 ≤3 且涨跌比 <35% → 半仓乘数强制 ×0.25。

**高潮易分歧**：前 5 板块均涨 ≥7% → 禁止新开（人人赚钱时离场）。

### 9 分共振（术）

| 维度 | 满分 | 判据 |
|---|---|---|
| ① 板块强度 | 2 | 板块排名 ≤8 且涨停 ≥2；板块内前 10% 再 +1（封顶 2）；后 50% -1 |
| ② 大盘趋势 | 1 | 上证上涨 **且** 在 MA20 上方 |
| ③ 消息面 | 1 | 有明确催化 |
| ④ 市值区间 | 2 | 50~300 亿最佳；<30 亿归零；>500 亿仅 1 分 |
| ⑤ 量价结构 | 2 | 放量上涨 + 均线多头；换手 >20%、量比异常等逐项扣分 |
| ⑥ 止损结构 | 1 | 止损 ≤8% 且 止损/ATR ≤2.5 且 R:R ≥3 |

**动态门槛**：基准 6，杂毛 +1，样本不足 +1，防守姿态 +1；种子龙头 -1（下限 6）。

### 身份判定（100 分制，6 维）

板块内排名、板块排名、个股 vs 板块涨幅、板块涨停跟涨、市值、均线。

```
龙头 ≥70 │ 跟风 ≥45 │ 杂毛 <45
```

**≥2 个负面 flag 强制降为杂毛** —— 分数好看但硬伤多的票不给通行证。

**热点板块相对跟涨**：极热板块（≥6%）内，相对系数 `个股涨幅/板块涨幅` 落在 0.42~0.90 → +18（跟得上但没透支）；板块前排 + 板块内前 40% 额外 +12。

### ATR 止损止盈（ATR 优先）

```
止损% = clamp(ATR% × 1.5, 2%, 8%)，硬顶 6%
止盈% = min(ATR% × 3, 15%)
```

**含滑点 R:R**（买入 +0.5% / 止损 -0.5%，只做悲观假设）：

```
R:R = (目标价 - 买入价×1.005) / (买入价×1.005 - 止损价×0.995)
```

要求 `R:R ≥ 3`；不足则抬高止盈反推，抬到 15% 上限仍不够 → 直接否决。

打平胜率 `= 1/(1+R:R)`。期望值 `E[R] = p̂ × odds − (1 − p̂)`，历史样本不足时按默认胜率 0.40 并标记 `样本不足`。

### 仓位（3/7 灰度确认制）

```
半仓额度   = 总资金 × 50% × 乘数
总股数     = floor(半仓额度 / (价格 × 100)) × 100
灰度仓 30% ──突破确认──> 确认仓 70%
乘数 = 情绪乘数 × 期望值乘数 × 跟涨乘数，夹紧 [0.25, 1.0]
```

先用 30% 试错，方向对了再补 70%。错了只亏 3 成。

### VETO 一票否决（术）

| 硬否决（直接毙） | 软否决（进观察轨，不买） |
|---|---|
| 涨停区 ≥9.5% | 接近涨停 ≥9% |
| ST / *ST | 龙头乖离 >20% |
| 换手 >25% | 普通股乖离 >15% |
| 无板块交易权限 | 分时位置 >75%（龙头 >85%） |
| 乖离 MA20 >30% | |
| 分时位置 ≥95% | |

20cm 板（创业板 / 科创板）阈值等比 ×2。

## 六、纪律硬约束

这几条**不接受 FORCE**，是引擎存在的理由：

1. **计划绑定** —— 今日无有效计划，或代码不在计划内 → 禁止评估、禁止买入。
2. **买入窗口** —— 非 14:00–14:45 → 禁止新开。
3. **单日限额** —— 每日最多新开 1 笔、评估 5 次、同一标的复筛 2 次。
4. **上证 MA20 下方** → 禁止评估新开。
5. **姿态空仓 / 高潮易分歧** → 禁止买入。
6. **连亏冷却** —— 连续亏损达阈值 → 强制冷却期。
7. **VETO 硬否决 / 共振分不足 / R:R <3** → 禁止买入。

## 八半、多数据源与降级

单一源的问题不是会不会挂，而是挂的时候整轮评估直接停摆。引擎支持按顺序降级的多源链：前一家取不到就自动问下一家，上层拿到的字段与单位完全一样（以东财 schema 为准：价格元 / 成交量手 / 成交额与市值亿）。

| 源 | 实时行情 | 日 K 线 | 指数快照 | 编码 | 备注 |
|---|---|---|---|---|---|
| `eastmoney` 东财 | ✓ | ✓ | ✓ | UTF-8 | 字段最全（量比 / 换手率 / 市值 / 行业），链上的首选主源 |
| `tencent` 腾讯 | ✓ | ✓ | ✓ | GBK | 字段次全；成交额原为万元、已换为亿 |
| `sina` 新浪 | ✓ | ✓ | ✓ | GB2312 | 无量比/换手率/市值（置 None）；必须带 Referer |
| `netease` 网易 | ✓ | — | — | UTF-8 | 代码前缀沪 `0` / 深 `1`；无量比/换手率/市值 |
| `ifeng` 凤凰 | — | ✓ | — | UTF-8 | K 线字段序为开/**高**/**收**/低；不给成交额 |

一家源只实现它真有的那几项，其余方法抛 `NotImplementedError`；降级链遇到它**静默跳过、不计失败**，直接问下一家。所以全开时：

- 报价：东财 → 腾讯 → 新浪 → 网易（凤凰被跳过）
- 日 K：东财 → 腾讯 → 新浪 → 凤凰（网易被跳过）
- 指数：东财 → 腾讯 → 新浪（且单家内部再分报价/K 线两路互为兜底）

“没能力”与“取数失败”分开计：最终报错只会列真正失败的源。响应合法但确实无数据（停牌 / 新股没 K 线）也不会被当成故障。

**板块排名 / 板块成分 / 涨跌家数 / 涨停池不在降级范围内**——这四项别家没有对等接口，仍由东财直连。东财整体不可用时这几项依旧会失败，因此它们的重试单独压得更低（`market.member_retries`）：扫 30 个板块时每一环都死磕到顶，总耗时会从几十秒满到几分钟。

默认就是五家全开（`market.data_sources`）：只包东财一家的降级链等于没有降级。单源时代落盘的老配置会在下一次启动时自动升级一次（屏上会提示，标记在 `meta.multisource_migrated`，只做一次）。想换组合：

```bash
# 退回单源（不推荐：东财一抖整轮就失败）
python3 -m tea config set market.data_sources '["eastmoney"]'
# 只要三家都有报价与 K 线的
python3 -m tea config set market.data_sources '["eastmoney","tencent","sina"]'
```

切源时屏上直接报「谁挂了、改用谁」（`⏳ 东财行情失败（...），改用 腾讯 数据源...`），收尾另报一行命中账（`网络请求 68 次｜东财 45｜腾讯 18｜失败 0`）。同一家源只重试 `market.retries`（默认 2）次：后面还有四家备源，在第一家身上死磕只是把降级往后拖。

首次启动向导（`tea setup`）也会问一次，三个预设：全部（默认）/ 东财+腾讯+新浪 / 仅东财。

每家每方法的超时单独配（`market.provider_timeouts`）：备源存在的意义是快速接手，沿用主源的 8s 会把一次四级降级拖到 30s+，所以备源一律给得更短（腾讯/新浪 4s、网易 3s、凤凰 5s）。全局防封层（UA / Referer / CDN 轮换、退避重试、坏节点黑名单）五家共用。

### 网络要求

五家源分布在四家公司的域名上，防火墙 / 代理只放通其中一部分时，降级链会退化成「每次都先等主源超时再白试几家」，比单源更慢。要全开五源，需要放通：

| 源 | 域名 | 用途 |
|---|---|---|
| 东财 | `push2.eastmoney.com`（含 `82.push2` / `push2delay` 镜像） | 报价 / 板块 / 涨跌家数 |
| 东财 | `push2his.eastmoney.com`（含 `1.` / `2.` / `7.` 镜像）、`push2ex.eastmoney.com` | 日 K 线 / 涨停池 |
| 腾讯 | `qt.gtimg.cn`、`web.ifzq.gtimg.cn` | 报价 / 日 K 线 |
| 新浪 | `hq.sinajs.cn`、`money.finance.sina.com.cn` | 报价 / 日 K 线 |
| 网易 | `api.money.126.net` | 报价（HTTP，非 HTTPS） |
| 凤凰 | `api.finance.ifeng.com` | 日 K 线 |

另外两条容易被内容安全代理拦掉的细节：

- 新浪报价必须带 `Referer: https://finance.sina.com.cn`，缺了直接 403（这是硬性要求而非防封优化，可用 `market.sina_referer` 改）。剥离请求头的代理会让新浪这一环恒定失败。
- 网易只有 HTTP 接口（`http://api.money.126.net/...`），强制 HTTPS 的代理下这家取不到数。

内网 / 白名单环境如果只允许访问东财，建议直接退回单源，别让每次取数都白等四家超时：

```bash
python3 -m tea config set market.data_sources '["eastmoney"]'
```

单源时的用户反馈由抓取层兜底：某个域名的重试全部用尽时报一句 `⏳ push2.eastmoney.com 网络抖动（2 次尝试均失败），即将切换...`（重试过程中不再逐次刷屏，节流间隔见 `market.retry_notice_gap_sec`）。

## 十、离线自测

```bash
python3 -m tea selftest
```

自测**不联网**，用构造行情跑全链路。关键点：每一项断言都在测试内**按规格独立重算一遍**再和引擎比对，所以它能抓住"实现和规格分叉"，而不只是"代码没崩"。

覆盖范围：情绪分逐项复算 + 冰点降仓、身份 6 维 + 分数夹紧 + 杂毛强制降级、ATR(14) + 止损止盈 + 含滑点 R:R + 反推止盈、9 分共振六维逐项 + 扣分项、VETO 全部阈值边界（含 20cm ×2 放大与权限）、仓位与期望值公式、三道门禁 7 条规则、种子四步流、行情解析量级（fltt=2 不再缩放，含尺度无关的涨幅自洽断言）、clist 翻页（精确涨跌家数 + 板块成分不被前 100 名截断）、涨停池按交易日回退、**五源降级链（四家报价源单位对齐 / 凤凰开高收低异序 / 部分能力静默跳过 / 错误汇总只列真失败）**、菜单分组与时段建议、首次启动向导（落盘 / 输入校验 / 标记幂等）、`run_once` 端到端（BUY → 灰度仓 → 补确认仓 → 平仓 → 门禁拦截当日第二次评估）。

当前：**352/352 通过**。

自测在临时 `TEA_HOME` 沙箱中运行，不会碰你的真实数据与报告。

## 十一、验收对照

| 验收项 | 入口 | 自动断言 |
|---|---|---|
| 输入代码 → 行情 → 板块/身份/9分 → BUY/REJECT | `run` `eval` | ✓ 端到端 |
| seed-plan → TOP 板块 → 三档筛选 → VETO → 预审 → 写计划 | `seed-plan` | ✓ 四步流 |
| plan-check → 快照对比检测变动 → 作废/有效 | `plan-check` | ✓ 计划有效性与 `executed` 标记 |
| 市场天气 → 情绪评分 → 姿态判定 → 冰点降仓 | `weather` | ✓ 逐项复算 + ×0.25 |
| 门禁：时间窗/计划绑定/MA20/单日限额 | `gate` `status` | ✓ 7 条规则 |
| VETO：涨停/乖离/分时高位/换手/ST | 内置于评估 | ✓ 15 个阈值边界 |
| 仓位：3/7 灰度 + 半仓乘数（情绪×期望×跟涨） | `pos` `add-confirm` | ✓ 公式 + 整手向下取整 |
| 观察池：纳入/剔除/回踩就绪 闭环 | `watch` `review` | — 命令已通，未单独断言 |
| 身份判定：龙头/跟风/杂毛 + 杂毛预警抬门槛 | 内置于评估 | ✓ 6 维 + 门槛 6→7 |
| 防封：随机UA/Referer/延时/代理池/缓存 | `data/fetcher.py` | — 自测离线，不覆盖网络层 |

两项标 `—` 的是实现完成但没有自动断言：防封属网络行为，离线自测按设计不触网；观察池闭环由 `seed-plan` → `review` 贯通，建议实盘第一周人工比对一次。

> 注意：自测全程离线，因此**东财接口的真实连通性（URL、字段映射、防封节奏）尚未经过验证**。公式是确定的，网络层只能证明结构完整。建议盘中先跑 `tea weather` 与 `tea eval <代码>` 实际验一下。

## 十二、打包发布

在**自己电脑上调试完**，一键打成可分发的桌面程序：

```bash
python3 packaging/build.py
```

脚本按 `sys.platform` 自动选形态，不用记参数：

| 在哪台机器上跑 | 产物 | 形态 |
|---|---|---|
| macOS | `dist/TEA.app` | onedir + .app bundle |
| Windows | `dist/TEA.exe` | onefile 单文件 |

> PyInstaller **不能交叉编译**：要 Windows 的 `.exe` 就得在 Windows 上跑一次，Mac 上只能出 `.app`。在其他系统上执行会直接报错并提示改用源码运行。

首次打包会自动 `pip install pyinstaller`（dev-only 依赖，运行时用不到；也可以先 `pip install '.[build]'`）。

每次打包都会**先删掉 `dist/` 与 `build/` 再重新生成**，不会撑着上一轮的残留；想留旧产物就先自己把 `dist/` 拷走。

常用开关：

| 参数 | 作用 |
|---|---|
| `--onefile` | 强制单文件（macOS 上会得到命令行可执行文件而非 `.app`） |
| `--no-console` | 隐藏控制台，**仅 Windows**；TEA 是交互式 CLI，默认保留 |
| `--bundle-config` | 把 `tea_config.json` 作为默认模板打进包（默认不打，见下） |

### 打包版的数据写在哪

`.app` / `.exe` 内部是只读的（macOS 还要过签名校验），持仓与缓存不能往里写。所以运行时数据目录按三级优先级解析（`tea/core/paths.py`）：

| 优先级 | 位置 | 何时生效 |
|---|---|---|
| ① | `$TEA_HOME` | 你显式设了就以你的为准 |
| ② | `~/.tea/` | 打包版默认，自动创建 |
| ③ | 当前工作目录 | 源码运行，**行为与以前完全一致** |

也就是说：源码跑还是落在仓库根的 `data/` 与 `reports/`，打包版跑落在 `~/.tea/data/` 与 `~/.tea/reports/`，两者互不干扰。想让打包版也用某个固定目录，设 `TEA_HOME=/path/to/dir` 即可。

> **别把带隐私的配置打进包。** `tea_config.json` 可能含代理账号密码与本金，因此默认**不**随包分发（这也是它被 `.gitignore` 排除的原因）。确实要带一份默认模板给自己用时才加 `--bundle-config`，且不要把产物转发他人。
